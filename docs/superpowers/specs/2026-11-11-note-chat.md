# Chat about a note

Requested: an in-app chat window to clarify a note. User selected persistent history per note.

Open “Hỏi về note” on a saved note. A right-side chat window retains the reading context behind it and becomes full width on mobile. Closing does not discard history or interrupt an in-flight turn. Escape closes; focus returns to the opener. Markdown responses reuse the existing renderer.

Backend reads the owned saved note, never trusts a supplied note body or transcript. Explicitly ask users to save edits first. Chat uses ChatGPT, OpenAI or DeepSeek through the existing client. It explains text, gives examples, and answers follow-up questions without editing notes. Images are not sent to the model. Provider receives saved note text and the latest bounded conversation context only after Send.

A private note_chat row stores complete successful turns, revision and an expiring request lease. Composite foreign key enforces ownership and cascades deletion with the note. Publication and clone never share chat history. Atomic lease/revision checks prevent concurrent and stale turns; completed request IDs make retries idempotent. Failed requests release the lease without adding partial transcript. No DB transaction is held across AI calls.

Limits: question 2,000 characters, note context 40,000 characters, answer 16,000 characters, 50 successful turns. Use latest 12 turns within 24,000 characters as conversation context and label this in the UI. A confirmed clear action resets conversation. Loading/error/retry states preserve typed questions. Tests cover authorization, prompt context, failures, concurrency, persistence and UI behavior.
